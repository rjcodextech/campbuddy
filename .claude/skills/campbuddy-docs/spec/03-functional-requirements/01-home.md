# 3.1 Home

[← Index](00-index.md) · Next: [3.2 Event branding →](02-branding.md)

Home is the most important screen in CampBuddy and must not become a generic card dashboard — its one job is answering "what should I do right now," and its content changes based on the selected event, current date/time, saved sessions, completed quests, onboarding preferences, and Contributor Day status.

| ID | Requirement |
|---|---|
| H1 | **Happening Now**: what's currently underway — registration open, keynote in progress, lunch started, Contributor Day tables open, networking hour — derived from the event's schedule data ([3.3](03-roster-ingestion.md), [3.8](08-my-day.md)) compared against current time, not manually authored per-event unless an organizer overrides it. |
| H2 | **Up Next**: upcoming activities, prioritized in this order — (1) the attendee's own saved sessions ([3.8](08-my-day.md)), (2) important event-wide activities (keynote, lunch, closing), (3) sessions matching the attendee's stated interests from onboarding ([3.11](11-onboarding.md)). |
| H3 | **Suggested Action**: an occasional, single, simple nudge — "visit the sponsor area," "introduce yourself to someone from another city," "add your LinkedIn to your Camp Card," "bookmark your afternoon sessions." Rotates from a mix of default CampBuddy suggestions and unfinished Quests ([3.6](06-quest.md)). Tone must read as helpful, not nagging — one suggestion at a time, not a list. |
| H4 | **Progress**: a compact, non-gamified indicator of Quest completion and saved-session count — small enough that WordCamp itself, not the app, stays the main event ([1.0 principle 1](../01-project-overview.md#10-product-philosophy)). |
| H5 | All copy on this screen follows the "guidance over information" translation pattern ([1.0](../01-project-overview.md#10-product-philosophy)) — a raw schedule fact is never shown without also saying what the attendee might do about it. |
| H6 | Home renders from already-downloaded event data ([5.1](../05-system-architecture.md#51-request-flow-public-pages--updated-for-server-rendering), [4.4 offline-first](../04-non-functional-requirements.md#44-offline-first)) — no blocking network call between opening the app and seeing a populated Home screen. |

> **Current implementation note:** Home also carries a hero section (event logo/name/dates) and a "Find people who match your interests" entry point above Happening Now — see [What CampBuddy does](../../about/02-what-it-does.md) and [3.4 Matching](04-matching.md).
>
> **Before Home:** `/` (`resources/views/welcome.blade.php`) is the always-reachable WordCamp picker attendees land on before any event is selected — every upcoming event (up to 100), soonest first (`HomeController`), each rendered via the reusable `<x-attendee.event-card>` component (`resources/views/components/attendee/event-card.blade.php` + `components/_event-card.scss`) in a `.card-grid`. Layout is `.event-card__main` (a row: avatar-shaped event icon on the left, date/title/venue on the right — date shows a range if `starts_on`/`ends_on` differ, single date otherwise, venue from `Event::info['venue']`) with a full-width "View event →" footer below it, separated by a hairline border. The component is generic (also takes `mediaUrl` as a 16:9 banner, `category` badge, `tags`, and a `qrCode` slot) — the picker is just its first real usage, not its only intended one.

> **Current implementation note:** the CampBuddy logo in the top bar — on every attendee screen and on the picker page itself — is a link to the WordCamp picker (`/`), the same destination as the "WordCamp's" button beside it, so tapping the brand always gets you back to the start.

> **Current implementation note (page titles):** the tab title names where you are. The picker (`/`) is **"CampBuddy | Your WordCamp companion"**; every event page is **"{Tab} | {Event name} | CampBuddy"** — *Home*, *My Day*, *Quest*, *Contribute*, *Explore*, *Camp Card*, *Remove me from the attendee list* (`<x-attendee-layout :event title="…">`, brand strings in `config/campbuddy.php`). Explore's and My Day's in-page tabs put the active section in front while you switch (*"Sponsors | Explore | WordCamp … | CampBuddy"*; `page-title.js`). Admin and sign-in pages use the same separator: *"Events | CampBuddy Admin"*.
>
> **Picker:** each card's avatar is the event's favicon, else its logo, else CampBuddy's icon, and falls back to CampBuddy's icon if the image fails to load. The picker lists **every** upcoming event (5 shown at first, see below), **soonest first** by start date (ties by id, so the order never shuffles; an event with no dates yet goes after the dated ones). An event counts as upcoming until its last known day has passed — its end date, or its start date when there is no end date — so a single-day event drops off the day after, and one in progress stays. Only `active` + visible events are listed (up to 100; beyond that reachable by URL only).

> **Picker country filter + Load more (29 Sep 2026):** the page carries every listed event (same HTML for every visitor, so still edge-cacheable); `resources/js/attendee/picker-filter.js` then shows the first **5** matching cards and a **"Load N more"** button that opens 5 more at a time. Cards are only shown/hidden, never built or copied, so no event can repeat and every count is a count of real cards. The visitor's country comes from the browser time zone (the idea of the owner's `timezone-country.js`: `Intl` zone → country): the page embeds, per listed country, all its IANA zones (`EventCountry::timezones`, JSON `#picker-countries`) and the JS keeps a small alias map for old names Chrome still reports (`Asia/Calcutta`). If the visitor's country has a WordCamp the list starts filtered to it. Layout: a pill **Country** dropdown with a map-pin inside (only as wide as its longest option; `All countries (N)` + each listed country with its count; brand-coloured edge while a country is chosen), beside it one chip — **✕ Show all** removes the filter, **Only India** puts it back — and under them the count ("Showing all 3 WordCamps in India" / "Showing 5 of 11 WordCamps"). No WordCamp in my country → all events, no "Only …" chip. At 320px the chip drops under the pill. Only one country listed → no filter bar, Load more only. Every filter change starts again at 5. The choice (`all` or a code) is remembered per device in `localStorage` (`campbuddy.pickerCountry`) and kept the same across open tabs (`storage` event); a remembered country with nothing listed is ignored. Without JS the filter stays `hidden` and every card shows. An event's country (`App\Support\EventCountry::code`): `events.country_code` (migration `2026_10_03_090000`, filled from the time zone for existing rows) → its time zone → the last part of its venue line; none = listed only under "All countries". `php artisan campbuddy:countries [--refresh] [--offline]` fills the column from central.wordcamp.org's `_venue_country_code` (else time zone / venue); it writes the row directly so no fetch jobs re-run. Tests: `tests/js/picker-filter.test.mjs`, `HomePickerTest`, `EventCountriesCommandTest`, `Unit/EventCountryTest`.


> **Current implementation note (first-timer guidance):** Home now answers "what should I do" for newcomers explicitly. Order: hero (with a live status line — *Starts in 3 days* / *Day 1 of 2 · happening now* / *finished*) → starting-soon banner → **"New to WordCamp? Start here"** card (links to the event's Guide; hidden once dismissed or when onboarding answered "not my first WordCamp") → Happening now → Up next → One thing to try → Meet people → Progress. **Happening now** lists *every* concurrent session (so a first-timer sees they have a choice) plus one line of what to do; before the event it becomes a short prep checklist, after it a wrap-up. **Up next** follows H2's priority within short windows (saved: 2 h, event-wide moments such as keynote/lunch: 30 min, interest matches: 1 h). The "what to do" copy (H5) lives in `App\Support\FirstTimerGuide::moments()`; schedule items are matched by whole word, and break/meal moments never match talks (`resources/js/attendee/moments.js`).
>
> **Guide (WordCamp 101):** `/guide` (before an event is picked, linked from the picker) and `/event/{slug}/guide` (topbar **Guide** button on every event screen). What a WordCamp is, how the day usually goes (with this event's real times filled in by `guide.js`), a glossary, tips, what to bring and an FAQ — content in `App\Support\FirstTimerGuide`, markup in `attendee/partials/guide-body.blade.php`.

> **Current implementation note (explaining the use case, students):** after feedback that visitors didn't understand what CampBuddy is for, the picker (`/`) carries `attendee/partials/about-campbuddy.blade.php`: a four-step "How CampBuddy helps you at WordCamp" infographic under the intro (Know what's happening → Plan your day → Meet your people → Stay in touch; "Free · No account, ever · Works on bad venue wifi"), and below the event list a **"See it in action"** tour — the app's real screens (`public/media/tour/*.jpg`, captured from the demo event) in a phone frame, advancing like a short silent video (`tour.js`: pauses on touch/hover/focus and off screen, never auto-plays with reduced motion, tracked as `tour_view`) — then **"Made for"** cards (first WordCamp · college students · been before) and a short FAQ. College students get their own Guide section (`#guide-students`, `FirstTimerGuide::students()`: student tickets, beginner-friendly talks, Contributor Day as résumé-worthy open-source experience, talking to sponsors about internships, volunteering, learn.wordpress.org, a student 15-second intro), a "Student" onboarding choice that favours beginner/career sessions on Home, `student` and `mentor` discovery tags, and a "Career Chat" default quest. To refresh the tour screens after UI changes, re-capture them from the demo event at 360 × 720 @2×.

> **Line icons instead of emoji (Sept 2026, owner's request).** Picker "Who it's for" cards, the event card's location, Home's tip card, the Guide (hero badges, day timeline, tips, students, "at this event" rows, next-step cards), Explore → Event Info rows, Quest cards and Contribute team cards use outline SVG icons (Lucide shapes, 1.8px round stroke, brand colour) instead of emoji, so they look the same on every phone. One list: `App\Support\LineIcons::ICONS`; every attendee page gets them once as an inline sprite (`attendee/partials/line-icons.blade.php`, included from `templates/shared`, so offline works); Blade uses `<x-attendee.line-icon name="…" />`, JS `lineIcon('…')` (`line-icon.js`, clones `#tpl-line-icon`). Data carries icon names: `FirstTimerGuide` day/tips/students `icon`, `quest.js` `THINGS_TO_DO_META`, `contrib-teams.js` `icon`. Symbols that act as text (✓ ✕ ★, 👋 Wave, 🎉 in messages, the tour's ❚❚) are unchanged. Tests: `LineIconsTest` (every used icon is in the sprite, no emoji left in those boxes, data names real icons).
