# 3.5 Schedule & notifications

[← Index](00-index.md) · Previous: [3.4 Interest-based matching](04-matching.md) · Next: [3.6 Quest →](06-quest.md)

| ID | Requirement |
|---|---|
| N1 | Bookmarking a session stores it locally. Notification permission is **never requested on page load or app open** — it's asked right after a bookmark, at the moment the benefit is obvious: *"Want CampBuddy to remind you before this session starts?"* If granted, a scheduled Web Push registers for 5–10 minutes before start, including track/hall. |
| N2 | Every device also gets an in-app "starting soon" banner/badge for bookmarked sessions regardless of push support — this is the guaranteed path, push is a bonus. |
| N3 | iOS: push requires iOS 16.4+ **and** the PWA installed to the home screen first; the app explicitly detects this and shows an iOS-specific instruction instead of a silently-failing permission prompt. |
| N4 | A denied permission is **respected permanently** — CampBuddy never re-prompts automatically. Re-enabling push is only ever a deliberate action the attendee takes from a settings surface, never a repeated browser prompt. |

> **Current implementation note (N3 now actually shows, and only once):** `push.js` checked "is Web Push supported?" *before* "is this iOS outside the installed app?" — but in an ordinary iOS Safari tab `Notification`/`PushManager` don't exist, so the answer was always "unsupported" and the iOS instruction never appeared. The iOS check now comes first, uses the shared `platform.js` (`isIos()` also recognises iPadOS, which sends a Mac user agent), and the instruction is shown **once per device** (`notificationState.iosInstallPromptShown`), not on every saved session (N1's "never nag").
>
> **Current implementation note (Oct 2026, iPhone hint in My schedule):** after that one dialog every later save on an iPhone browser tab stayed silent, so people took their reminders to be set (GA, WordCamp Rajasthan 2026: 13 of 15 `ios_needs_install` offers). `ios-reminder-hint.js` now keeps a quiet card above *Talks & sessions* in My Day → My schedule — only on iPhone/iPad, in a browser tab (not the installed app), with ≥1 saved session — saying reminders need the Home Screen and that until then the Home tab shows "starts in … min" (N2). **Show me how** opens the same install steps as the header's Install app button (`install.js` `openInstallSteps()`); **✕** hides it for good on that device (`localStorage` `campbuddy:ios-reminder-hint-dismissed`). It asks nothing and touches no permission. The N3 dialog gained the same "until then" line. GA: `reminder_ios_hint` with `result` = view / open / dismiss.

> **Memories (10 Oct 2026, owner confirmed twice):** after the event an admin (Admin → Event → **Memories**) or the event's managers (same tab, changes logged as section `memories`) add the **photo album** link (any `https://`) and the **WordPress.tv speaker sessions** link (`wordpress.tv` host only) — `events.photo_album_url` / `wordpress_tv_url`, `App\Support\EventMemories`. Each link has its own **Send to N phones** button: one push (`SendMemoriesPushJob`, TTL 2 days) to every `push_subscriptions` row of that event, **once per kind** — `photo_album_notified_at` / `wordpress_tv_notified_at` are claimed in one conditional UPDATE, so a double click or two organizers still send one. With no phone subscribed yet the button is hidden and the send refused (it would use up the one send). The push opens `/event/{slug}/memories` (`EventMemoriesPageController`), not the raw link, so a link fixed after sending still reaches everyone. That page is **not** behind `event.public`: it stays open for an *archived* event (WordPress.tv videos arrive weeks after the 7-day retention), still 404s a draft or hidden one; standalone page (no tab bar, no app.js), `noindex`. While the event is live, Home shows a **Memories** card (`attendee/partials/memories-card.blade.php`) when a link is set; the links are in DataVersion so open apps refresh. Tests: `tests/Feature/EventMemoriesTest.php`.

> **After-event pushes (12 Oct 2026, owner confirmed twice).** Every push about an event goes once, to every `push_subscriptions` row of that event, in the venue's daytime (11:00–19:00), within `RETENTION_DAYS` (30) of its last day:
> - **Day 3** — thank-you (rating + PDF), `SendThankYouPushJob`, as before (`thank_you_sent_at`).
> - **Day 7** — *"Keep your {event}"*: sessions, people and notes live only on the phone; opens `?export=1` (thank-you card with the PDF). `SendAfterEventPushesJob`, `events.save_data_sent_at`.
> - **Day 15** — *"New phone, or your next WordCamp?"*: opens `?move=1`, the **Take it with you** sheet (`attendee/partials/move-data.blade.php`, `move-data.js`, on a finished event's pages): bring the profile and the people met to the next WordCamp (picker link), move CampBuddy to a new phone (the device-transfer steps: on the new phone Explore → People → Join → pick your name → 6-digit code, typed on the old phone; for people who joined Meet people with their roster name; until the retention end), or save the PDF. Also reachable from the thank-you card ("New phone or next WordCamp? Take it with you"). `events.move_data_sent_at`. An event first seen after day 15 gets only this one (and is marked as having had day 7). Hourly at :10 (`send-after-event-pushes`). **Changed 12 Oct (owner): next WordCamp only, no "new phone".** Title *"Going to another WordCamp?"*; the payload carries `needs: "bring"` + `eventId`, and `sw.js` (`holdsBringable`, same test as `bring-data.js` `worthBringing`: a Meet people profile with answers, or a named, visible person met) shows it only on a phone holding something to bring; otherwise nothing is shown. The sheet and the thank-you link ("Next WordCamp? Bring your people along", `hidden` until checked) also appear only then. The sheet now offers next WordCamp + PDF; device transfer still exists under Explore → People.
> - **Photo album / WordPress.tv** — by an admin or manager (Event → Memories), as before.
> Every push is logged in `events.push_log` (kind → time, phones) by `App\Support\EventPush` (shared send + log; the thank-you and memories jobs log too) for the Notifications tab. Migration `2026_10_12_090000_add_after_event_pushes_to_events`. GA: `move_sheet_view` (surface push | thank_you), `move_sheet_action` (method next_wordcamp | pdf). Tests: `AfterEventPushesTest`, `tests/js/move-data.test.mjs`.

> **Memories everywhere people come back to (12 Oct 2026).** The photo album / WordPress.tv links also show on the picker's *Completed* card (a row between the card and *Save your WordCamp Data*, `.event-card__memories`) and in the thank-you card (*Relive it*). Every such link reports GA `memories_open` (target photos | videos).

> **Notifications turned down: what it turns off, and the way back (31 Oct 2026, owner confirmed; web + native 0.0.23).** The consent bar is only Google Analytics; saying no to it turns nothing else off (device ID, reminders, organizer updates, photos all work), so nothing says otherwise and "Turn on all" never includes analytics (owner's choice; India's 2023 dark-pattern guidelines / DPDP s.6). After a **no to notifications** — "No thanks" to the reminder question, "Not now" on the live-updates card, the browser's/phone's own block, or a yes later switched off in settings — a card **"Notifications are off"** (only what is really off: *a reminder before the talks you save*, *live updates from the organizers*; "Everything else still works: …") with **Turn on notifications** / **Not now** shows right after the no, then on Home and My Day at most once a day (`campbuddy-off-hidden:{slug}` / app `notif:off:hidden:{slug}`), only until the event's last day, and on Home not while the live-updates card is still asking. **Your choices** (after *Your data*: web Explore → Info and Camp Card; app My Day and Explore) shows Talk reminders / Live updates (On, Off, Blocked) with **Turn on all**, and on the web the analytics answer + "Change analytics choice" ("Saying no to analytics changes nothing else"); the app says it has no analytics. N4 holds: the browser/phone question only comes from a tap. A blocked browser can't be asked again, so the web shows where to allow (installed app vs. browser tab) and finishes by itself when allowed (Permissions API `change` / visibility); the app opens CampBuddy's notification settings (`ReminderPlatform.openSettings`, Android `ACTION_APP_NOTIFICATION_SETTINGS`, iOS Settings URL) and polls for a minute or three. Turning on syncs a reminder for every saved talk still ahead (outbox when offline) in the background. Code: `resources/js/attendee/notification-choices.js`, `partials/notification-choices.blade.php`, native `domain/NotificationChoices.kt` + `ui/NotificationChoices.kt`; tests `tests/js/notification-choices.test.mjs`, `NotificationChoicesTest` (PHP + native).
