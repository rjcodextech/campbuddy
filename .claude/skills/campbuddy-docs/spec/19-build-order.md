# 19. Suggested build order (10-day window)

[← Back to index](../SKILL.md) · Previous: [18. Credits & license](18-credits-license.md) · Next: [20. Engineering principles →](20-engineering-principles.md)

Sequenced so that something demoable exists early, and every day ends with the app in a working (if incomplete) state rather than a pile of half-wired pieces. Each phase assumes the previous one is functional, not polished. Fallbacks are built before enhancements throughout (in-app banner before push, empty states alongside their screens, not after).

1. **Foundation.** Fresh Laravel 12 app, migrations for [7](07-data-model.md)'s tables, Breeze admin auth ([6](06-technology-stack.md)), WAMP vhost pointed at `public/` ([11.4](11-installation-setup.md#114-local-wamp-setup)). Done when: you can log into `/admin` locally.
2. **Event CRUD + first data pull.** Admin panel's Events Create/Read/Update ([9](09-admin-panel.md)), then `FetchSpeakersSponsorsSessionsJob` ([finding 0.1](00-findings.md), [5.2](05-system-architecture.md#52-ingestion-flow)) wired to WCR. Done when: WCR exists as an event record with real sessions/speakers/sponsors visible in the admin dashboard's ingestion status.
3. **Branding.** `FetchBrandingAssetsJob` + manual upload override + the visibility toggle (default on) + the contrast guardrail. Done when: WCR's actual logo renders on a test page. *(Color-specific steps here were later superseded — see [3.2](03-functional-requirements/02-branding.md).)*
4. **Onboarding + Home.** The 4-step flow ([3.11](03-functional-requirements/11-onboarding.md)) feeding Home's Happening Now/Up Next ([3.1](03-functional-requirements/01-home.md) H1–H2) against WCR's real schedule data. Done when: a fresh device can complete onboarding and land on a Home screen that's actually contextual, not placeholder text.
5. **My Day + session details.** Full Schedule, My Schedule, session detail, overlap warning ([3.8](03-functional-requirements/08-my-day.md)). Done when: a first-timer can browse WCR's schedule and build a personal day end to end.
6. **Camp Card + Quest.** F10 and F6 ([3.10](03-functional-requirements/10-camp-card.md), [3.6](03-functional-requirements/06-quest.md)) — both largely self-contained. Done when: a QR-scannable Camp Card generates correctly and a quest can be marked complete.
7. **Contribute.** The question flow + fixed team list + per-team explanations ([3.9](03-functional-requirements/09-contribute.md)). Done when: answering the questions produces a real, correctly-worded team recommendation.
8. **Explore — Sponsors, Deals, Event Info.** [3.7](03-functional-requirements/07-deals.md), [3.12](03-functional-requirements/12-sponsors-event-info.md) — mostly a display layer over data already ingested in step 2. Done when: WCR's actual sponsors and event info render correctly.
9. **Attendee roster + People matching.** `ParseAttendeeRosterJob` ([3.3](03-functional-requirements/03-roster-ingestion.md)) first, then the full discovery architecture — Join/Leave, anonymous IDs, client-side matching ([3.4](03-functional-requirements/04-matching.md), [8.3](08-security-privacy.md#83-matching-data--the-local-by-default-shared-only-by-choice-architecture)). Built last among the data features deliberately: it's the riskiest ingestion job and the most privacy-load-bearing feature.
10. **Sessions bookmarking + notifications.** In-app banner first (guaranteed path), Web Push second (best-effort, permission requested only after a bookmark).
11. **Data controls.** Export/Clear ([3.13](03-functional-requirements/13-data-controls.md)) — needs everything above to exist first, since it bundles all of it.
12. **Cross-cutting passes, run throughout rather than saved for the end:** empty states alongside each screen as it's built, accessibility checked per-screen not as one big audit, responsive testing after each major screen lands.
13. **Pre-launch blockers ([13](13-prelaunch-blockers.md)), run in parallel with steps 9–11 where possible:** Cloudflare live, `composer audit`, OWASP pass, the full acceptance journey ([15.2](15-testing.md#152-core-user-journey-acceptance-test)), LICENSE file, roster takedown path.
14. **Buffer + go/no-go.** Whatever's left unfinished a day or two out triggers the fallback decision in [14](14-fallback-plan.md) — decide deliberately, don't let the calendar decide by default.
